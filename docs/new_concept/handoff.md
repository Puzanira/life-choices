## 2. Поток экранов (state machine)

```
[ОПЕНЕР] --confirm--> [ИГРА (core loop)] --конец жизни--> [ФИНАЛ-НЕКРОЛОГ] --confirm--> [ОПЕНЕР]
```

- **ОПЕНЕР** — заставка с ироничными правилами (текст в GDD §3). Таймер стоит. Жмёшь «НАЧАТЬ ЖИЗНЬ».
- **ИГРА** — основной цикл (см. §3). Внутри — состояния-события: обычная карточка, рубрика-баннер, обучающая подсказка (пауза таймера), Блиц (2 сек/карта), импульс-раунд (INVERT), Депрессия (ч/б).
- **ФИНАЛ** — экран-некролог: причина конца + склеенная история (GDD §17).

---

## 3. Core loop (одна итерация)

1. Выбрать следующую карточку (по возрасту/условию/цепочке).
2. Счётчик возраста **плавно догоняет** возраст карточки (событийная модель времени, GDD §6).
3. Показать карточку + таймер 5 сек (Блиц — 2 сек). Ведущий может кинуть реплику-облачко.
4. Игрок отвечает: **ДА / СПАСИБО НЕ НАДО**. Не успел → случайный ответ (в INVERT-раунде молчание = ДА).
5. Применить последствия выбранной ветки: Δшкал + флаги (FATAL / OPEN / CHAIN / DELAY …).
6. Записать строку в память для некролога.
7. Параллельно всё время: дренаж шкал по реальным секундам, игрок руками поддерживает открытые шкалы.
8. Проверка конца: FATAL / здоровье=0 / энергия=0 / возраст=100 → ФИНАЛ.

## 4. Ввод: клавиатура сейчас → контроллеры потом

**Принцип (важно!):** игра слушает **смысловые события**, а не клавиши и не порт. Между железом и логикой — тонкий слой `InputSource`. Смена «клавиатура → COM-порт» = замена одного класса, логика не трогается. Реализация слоя — в прототипе (`prototype/game.js`, класс `KeyboardInput`), там же заготовка `SerialInput` под Web Serial / COM.

| Смысловое событие | Механика | Клавиатура (прототип) | Железо (потом) |
|-------------------|----------|------------------------|----------------|
| `ANSWER_YES` | ответ ДА | ← (стрелка влево) | рычаг влево |
| `ANSWER_NO` | ответ СПАСИБО НЕ НАДО | → (стрелка вправо) | рычаг вправо |
| `MONEY_TICK` | +1 щелчок дохода | Пробел (зажать/долбить) | энкодер-крутилка |
| `RELATION_AXIS(v)` | балансир отношений | ↑ / ↓ | джойстик (ось) |
| `ENERGY_PULSE` | «вдох» — восстановление энергии | E (ритмично) | дыхательный рычаг |
| `CHILD_PRESS` | реакция на вспышку ребёнка | Enter | кнопка с подсветкой |
| `CONFIRM` | старт/подтверждение экрана | Enter / Пробел | любая кнопка |

> **Контроллеры на автомате:** микроконтроллер (Arduino) читает ручки/рычаги/кнопки и шлёт по USB строки в COM-порт (напр. `MONEY_TICK\n`, `LEVER_L\n`). Игра (Chrome-киоск + Web Serial API) читает порт и превращает строки в те же `GameEvent`. Альтернатива — Arduino как HID-клавиатура (тогда вообще ничего в игре не меняется). Заложен вариант с COM-строками.

## 5. Как читать `scenes.csv` в код

Колонки: `ID, Карточка, Когда, Тип, ДА-последствия(проза), ДА-Δ, НЕТ-последствия(проза), НЕТ-Δ, Ведущий ДА, Ведущий НЕТ, Некролог ДА, Некролог НЕТ, Флаги`.

- **Проза «последствия»** — для людей, НЕ для кода. Логику бери из **Δшкал** и **Флагов** (машиночитаемо).
- **Δшкал** — формат `Абрев ±N`, через запятую: `Дн −1, Эн −1`. Абревиатуры: `Здр`=здоровье, `Эн`=энергия, `Дн`=деньги, `Отн`=отношения, `Реб`=ребёнок. Спецзнаки: `±N` = рандом в обе стороны; `→ 80%` = установить значение; `—` = нет эффекта. Знак минуса встречается юникодный `−` и обычный `-` — парсить оба.
- **Флаги** (через запятую):
  - `NOCONS` — без последствий (втягивание).
  - `FATAL` — выбор завершает игру (причина финала — из прозы/маппинга).
  - `OPEN:шкала` — открывает шкалу + обучающую подсказку.
  - `CHAIN→ID` — разблокирует карточку `ID`.
  - `DELAY(n)` — последствие срабатывает через ~n игровых лет.
  - `TIMELINE` — одноразовое событие (баннер-рубрика).
  - `RANDOM` — может выпасть в любой момент.
  - `INVERT` — импульс-раунд: молчание = ДА.
  - `BLITZ` — кризис-блиц: 2 сек, найти кнопку «ВСЁ НОРМАЛЬНО».
  - `ROND` — «неважная», можно выкинуть из некролога первой.
  - `ZONE` — шкала отношений (плохо и мало, и много).
  - `BLOCK$` — карточка недоступна без денег.
- **Возраст** (`Когда`) — задаёт порядок и порог появления; часто с условием (`если Отн открыта`, `если CH08=ДА`).
