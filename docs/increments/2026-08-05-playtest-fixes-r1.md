## 1. Пересказ дизайна

Основательница играла (клавиатурная эмуляция, без плат) и остановила тест — не
проходится туториал энергии. Её пункты, дословно:

1. **[БАГ, приоритет] Туториал энергии непроходим.** Даже со знанием клавиши
   (держать Q — подъём датчика A): «жму — ничего не происходит». Подозрение на
   системный конфликт: ритм-гейт дыхания принимает вдохи с интервалом
   **0.4–1.5 с** (BreathRhythm), а клавиатурная эмуляция пакета поднимает датчик
   со скоростью **0.5 ед/с** (rise от 0 до порога 0.5 = 1.0 с, сброс до 0.35 и
   новый подъём — цикл на грани/за верхом окна). ДИАГНОСТИРОВАТЬ через реальный
   путь: package KeyboardBackend-эмуляция → ArcadeInputSource → BreathRhythm →
   Game, с честными таймингами. Починить КОРЕНЬ (согласовать окно ритма со
   скоростью эмуляции / скорость эмуляции с окном — числа тюнимые, механика
   «дыхание ритмом» сохраняется). Туториал обязан проходиться живым человеком
   на клавиатуре за разумное время.
2. **«Это уже должно быть»: подсказки клавиш при эмуляции.** Когда ввод идёт от
   клавиатурной эмуляции (не от плат) — игра сама показывает зашитые клавиши в
   туториалах/подсказках, читая раскладку ИЗ КОНФИГА ПАКЕТА (не хардкод;
   CONTROLS_BRIEF: маппинг живёт в пакете). С платами строки не показываются.
3. **Убрать жёлтые баннеры-рубрики вех целиком** («СВЕТ! КАМЕРА! ЖИЗНЬ!»,
   «ПОРА ЗАРАБАТЫВАТЬ!» и т.д.) — их нет в присланных макетах. Вместе с их
   паузой «баннер-бит». Реплики Ведущего в облачке остаются.
4. **Текст задачи туториала отношений** → «Двигай джойстиком — сохраняй маркер
   отношений в зелёной зоне» (обновить канон host-content §4 + дрейф-гард).
5. **Отклик на невалидное дыхание**: видимая реакция на «жмёшь не в ритм»
   (вздрагивание/подсказка) + ритм словами в тексте задачи энергии.

## 4. Checkpoint log

- **(a) start:** прочитаны контракт, CONTROLS_BRIEF, пакет arcade-controls

- **(b) ДИАГНОСТИКА №1 (до правок).** Сим реального пути
  `HeightSimulator(0.5/0.5, hold-on-release) → ArcadeInputSource(0.5/0.35) →
  BreathRhythm(0.4–1.5) → TickNewScale(Energy>40 % + 1.5 c)`, шаг 1/60 c
  (скрипт: scratchpad `breath_sim.py` / `breath_sweep.py`). Результат:

  | сценарий (клавиатура) | принято вдохов за 60 c | туториал |
  |---|---|---|
  | «держу Q и не отпускаю» (что делала основательница) | **0** | **никогда** |
  | Q/A поровну, цикл 1.0 / 1.5 / 2.0 / 2.5 / 3.0 c | **0 / 0 / 0 / 0 / 0** | **никогда** |
  | Q/A по 0.3 c (теоретический минимум цикла 0.6 c) | **0** | **никогда** |

  То есть туториал энергии на клавиатуре **непроходим ни при какой каденции** —
  подтверждено. ДВЕ независимые причины, обе нужны для починки:

  1. **Эмуляция не возвращается в покой.** `HeightSimulator` при отпускании
     ОБЕИХ клавиш ЗАМИРАЕТ (`// both held or neither held: hold in place`).
     Держим Q → значение уезжает в 1.0 и остаётся там навсегда. Детектор вдоха
     (`ArcadeInputSource`: импульс на подъёме через 0.5, перевзвод при ≤0.35)
     выдаёт РОВНО ОДИН импульс за жизнь, а первый импульс в `BreathRhythm`
     всегда только «засевает» каденцию (`return false`). Итог: `_nsArmed`
     не взводится никогда → окно не закрывается. Это и есть «жму — ничего».
  2. **Порог недостижим за человеческий вдох.** rise 0.5 ед/с ⇒ от покоя до
     порога 0.5 нужна **ровно 1.0 c непрерывного удержания**. Любой цикл, где
     фаза подъёма < 1.0 c, не пересекает порог ВООБЩЕ — поэтому даже ручное
     чередование Q/A с циклом 1.0–1.5 c даёт ноль импульсов (а не «отбитые
     ритм-гейтом»: их просто нет). Плюс верх окна 1.5 c уже РЕЖЕТ комфортные
     2.0–2.5 c — это то, что подозревала основательница, но это лишь третья по
     счёту преграда, за первыми двумя её не видно.

  **Калибровка (выбранный вариант)** — согласованы три числа:
  `rise/fall 0.5 → 1.25 ед/с`, новый `return 2.0 ед/с` (пружина в покой,
  оба в конфиге пакета), `RhythmMax 1.5 → 3.0 c` (в игре). Пороги игры 0.5/0.35
  НЕ трогаем — это семантика физического датчика (ход через середину).
  Промежуточный кандидат rise 1.0 отвергнут (не брал короткий вдох 0.4 c),
  rise 1.5 — тоже (длинное удержание не успевало перевзвестись). После:

  | цикл, доля удержания 30 / 40 / 50 / 60 / 70 % | туториал закрыт |
  |---|---|
  | 1.0 c | — / 2.9 / 2.9 / 2.9 / 2.7 c |
  | 1.5 c | 3.4 / 3.4 / 3.4 / 3.4 / 3.4 c |
  | 2.0 c | 3.9 / 3.9 / 3.9 / 3.9 / 3.9 c |
  | 2.5 c | 4.4 / 4.4 / 4.4 / 4.4 / 4.4 c |
  | 3.0 c | 7.9 / 7.9 / 7.9 / 7.9 / 7.9 c |
  | 0.3–0.5 c (заколачивание) | **никогда** |

  Весь «удобный человеческий» диапазон 1.5–2.5 c проходит туториал за
  **3.4–4.4 c** (контракт: ≤~20 c) — и ОДНОЙ клавишей Q, без Q/A-чехарды.
  Механика сохранена: заколачивание клавишей физически не может дать импульс
  (порог не успевает набраться), а на ЖЕЛЕЗЕ (импульсы приходят напрямую)
  `RhythmMin 0.4` по-прежнему режет интервалы 0.1/0.2/0.3 c → 0 принятых.
